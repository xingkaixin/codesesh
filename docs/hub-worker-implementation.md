## 当前进度

已建立分支并保存设计基线。来源身份加入会话、存储关联、状态映射、HTTP 路径和浏览器引用。

本地来源在一个 Hub 内使用保留身份 `local`，远程来源由配对分配独立身份。
`local` 是持久的本地来源槽位，不表示当前进程是否启用采集；其全局归属还包含 Hub 身份。
旧会话与用户状态分别迁移时均映射到该保留身份，不需要跨库生成两次 UUID。
旧单机转远程 Worker 时，在发送入口映射到配对身份，不将 `local` 作为远端授权身份。
默认本机引用在 wire 中可省略来源，保留旧 URL 和游标；远程 URL 显式包含来源。

来源身份阶段已运行一次核心库测试：194 通过，3 个原有忽略项；后续新增迁移测试及 HTTP/前端变更仍在验证。

### 采集与持久同步基础

- 新增不加载价格表的采集模式，传输中显式保留估算输入。既有适配器定价测试增加无价格采集、JSON 往返和 Hub 重新估价的比较。
- Worker 专用 SQLite 只保留轻量采集基线与待确认内容；扫描进度和 outbox 同事务提交。
- 会话正文使用分片快照；元数据独立发送。分片确认后保留到整个快照提交确认，标题更新不会重传正文。
- Hub 接收内容和确认水位在一个 SQLite 事务中提交。相同序号及摘要可重试，跳号、摘要冲突、来源或恢复代号错误会拒绝。
- 远端来源身份由已配对节点决定；远程项目身份带节点前缀，不自动合并同路径项目。
- 已实现一次性配对令牌、节点凭据摘要和撤销的存储原语，尚未开放 HTTP/CLI 入口。
- 现有价格语义保持不变。尚未接入常驻周期刷新、节点界面与恢复任务。

本阶段定向测试：队列/协议 5 项、Hub 接收与配对 3 项通过；核心 Clippy 通过。
此前无价格采集接入后核心测试 200 项通过、3 项原有忽略。随后核心回归 203 项通过、3 项原有忽略；新增 Runtime 单 writer 发布测试也已通过（接收端定向共 4 项）。

### CLI、HTTP 与旧历史接入

- 增加 `hub`、`hub --scan-local`、`worker --hub`。默认单机入口保留；纯 Hub 不启动采集器，Hub 模式不回退到临时数据库。
- #651 迁移先于角色初始化；Hub/Worker 都保留 `--migrate-data` 确认。常驻进程锁不影响原有并发 JSON 扫描。
- 配对、心跳、上传使用独立 Worker 凭据。浏览器令牌不能作为 Worker 凭据，Worker 凭据不能访问浏览器查询接口；上传再次检查兼容性。
- Worker 使用单请求在途、重试退避及随机延迟。普通失联继续采集；明确不兼容或凭据拒绝暂停采集上传。
- 老数据库存在时要求 `--history import` 或 `--history ignore`，两者都不删除原文件；导入保留价格估算输入并通过 outbox 上传。
- Hub 每 6 小时检查价格缓存，单 writer 对历史估算重新计价，纯 Hub 无需本机扫描触发。
- Hub 本机采集保留已归档历史，不因来源日志删除而删除会话。
