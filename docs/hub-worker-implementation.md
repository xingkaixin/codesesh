## 实现要点

来源身份贯穿 SQLite、用户状态、FTS、成本事实、HTTP 路由、SSE 和客户端缓存。旧本机来源保留 `local` 与原 URL；远端来源由配对授权分配 UUID。独立配对注册库保留身份与凭据摘要，内容库重建不会要求所有 Worker 冒认新来源。

Worker 使用独立 SQLite 保存轻量基线与未确认队列，正文采用分片快照，元数据单独上报。扫描进度与出站数据同事务提交；Hub 内容与接收水位同事务提交。普通离线持续采集；明确拒绝跨重启保持暂停。Hub 单 writer 配合全局与每节点上传并发限制处理背压。

重采集任务与恢复代号持久化；恢复先重放待确认内容，再扫描仍存在的源。旧快照分片保留到整个快照确认。孤立元数据不会冒充完整会话，会保留缺失标识。改变 Hub 地址验证原身份；显式重新配对保留队列并建立新来源。

Hub 负责周期价格刷新和估算重算，用户状态归 Hub。Hub 本机采集保留归档，不因来源日志删除而删除历史。Worker 旧库导入和忽略都不删除原文件；#651 旧路径迁移在角色初始化前执行。

节点界面提供配对、改名、撤销、远程重采集、Agent 范围、队列与任务状态。节点会话浏览、搜索和概览支持来源筛选；远程会话标明来源并隐藏本机继续按钮。

## 具体实现选择

- 同步控制使用 `/api/worker/hello`，兼作心跳和任务领取。
- 第一版正文变化上传完整分片快照，尚无追加消息差分补丁优化；这是设计允许的快照路径，有明确带宽代价。
- 同步 payload/protocol 当前均为 1，独立于产品版本。后续修改必须维护准入范围。
- 节点关系采用 Hub 信息加分层节点列表，不引入图布局依赖。
- 本机内置采集器复用单机扫描器；持久远程任务管理已配对 Worker。统一管理本机任务可使用纯 Hub 加同机 Worker。
- Worker 逻辑队列清理后 SQLite 空闲页复用，不保证立即缩小物理文件。
- 代码和本机验证已完成；多机器、真实网络、跨版本制品和发布环境仍按验证清单分配，未标记通过。
