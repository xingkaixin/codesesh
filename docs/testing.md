# 测试取舍与平台边界

测试保护可观察的业务结果、危险的数据边界和已发生的回归。不按私有函数数量或覆盖率
补齐用例。相同逻辑集中在所属模块验证；组件只保留必要的接线、交互和恢复测试。
简单文案、CSS 类名、图标和绘图调用次数不作为单元测试契约。

## CI 执行范围

| 检查 | 执行平台 | 原因 |
| --- | --- | --- |
| Web、浏览器契约、脚本和完整 Rust 测试 | Linux | 解析、费用、搜索、树结构、事件合并和前端状态等纯逻辑使用相同实现 |
| rustfmt、生成契约漂移、发布流程模拟 | Linux | 与目标 OS/CPU 无关 |
| Clippy、原生构建 | 四个原生目标 | 编译平台条件分支和原生依赖 |
| Rust 平台测试子集 | macOS arm64/x64、Windows x64 | 文件元数据、监听、权限、锁、原子替换、SQLite 和子进程有平台差异；Linux 完整套件已包含这些测试 |
| CLI/HTTP/SSE 进程契约、退出与故障恢复 | 四个原生目标 | 验证真实二进制的进程、网络和持久化行为 |
| 打包与安装 smoke | 四个原生目标 | 二进制格式、tar 权限、路径和 launcher 有平台差异 |
| npm 安装 | 每个目标的 Node 22.0.0 / 24 | 验证最低支持版本与当前构建版本 |
| 浏览器 E2E、bundle 预算、算法增长率 | Linux | 应用行为和算法无需重复占用原生平台矩阵 |

`pnpm test:rust:platform` 使用 libtest 的多个过滤条件，执行以下现有测试：

- Core：discovery、migration、runtime、state、storage schema / memory、pricing manager、
  worker store，以及 Cursor、DSH、Kimi 的文件系统适配器测试和真实 Git worktree 测试。
- CLI：缓存路径、JSON 扫描、日志、价格刷新、原生服务和 Worker 连接。
- 独立进程：data_migration 和 hub_worker。

SQLite 的完整查询、聚合与同步协议矩阵由 Linux 完整套件验证；其他目标保留 schema、
重开数据库、并发写入、WAL 监听和真实 Hub/Worker 恢复等原生边界检查。适配器中的纯
投影测试不需要跨平台重复；上述混合模块保留整个小测试组，避免维护逐用例白名单。
改名或新增平台相关模块时，同步检查平台命令的过滤条件。Release 使用相同的分工。

## 核心覆盖率

覆盖率用于观察测试缺口。高门槛只适用于明确列出的会话数据、实时同步、分页、缓存
一致性和恢复入口，不把整个 hooks 目录当作核心。装饰动画不承担数据逻辑的覆盖率要求。
浏览器与 Rust 的数据完整性测试继续保留，删除展示断言不等于删除行为边界。

## 已退役的迁移差分

旧 Node 后端与 Rust 的 CLI、HTTP、适配器和缓存往返差分套件已完成迁移验收，现已删除。
CI 不再下载或启动参考后端。Rust 自身的 schema 升级、事务回滚和数据目录迁移测试继续运行。
`pnpm prepare:reference` 与 `pnpm bench:rust` 仅供手动重现历史性能对照，参考包不进入产品。
