# CodeSesh 产品定义

本文定义 CodeSesh 做什么、不做什么，以及取舍依据。新功能和重构先对照本文；与本文冲突的
改动需要先修改本文并说明理由。能力清单和 CLI 参数以 `README.md` 为准，术语以
`CONTEXT.md` 为准。

## 定位

CodeSesh 读取本机 AI 编码 Agent 的原生历史，归一为统一的会话，在 Web UI 中浏览、搜索和统计。
它是只读的历史工具：不改写 Agent 数据，不代替 Agent 执行任务。

## 目标用户

同时使用多个 AI 编码 Agent 的个人开发者。需要找回旧会话、核对用量和成本、复用过去的解法。

部分用户的会话分散在多台机器上，或希望 CodeSesh 常驻运行。他们使用 Hub/Worker 模式。

## 核心任务

| 任务 | 含义 | 主要能力 |
| --- | --- | --- |
| 找回 | 跨 Agent、跨项目定位某段对话 | 结构化搜索、项目分组、文件活动索引、收藏 |
| 看清 | 了解用了多少、花了多少、做了什么 | Dashboard、Token 与成本、智能标签、会话收据 |
| 复用 | 把过去的会话带回当前工作 | 完整回放、Markdown 复制、恢复命令 |

新能力应能明确归入其中一项。无法归入的能力默认不做。

## 目标

- **零配置**：不带参数运行即可自动发现受支持 Agent 的历史。
- **数据留在用户手中**：默认只在本机运行；Hub/Worker 仅在用户自托管的机器间传输，没有账号和云端遥测。
- **忠实呈现来源**：解析不了的字段显示为未知，不推测、不补造；用量和成本区分记录值与估算值。
- **大历史可用**：首屏先显示时间窗口内的数据，历史在后台回填，中断后可续传。
- **两种运行模式**：
  - **单机模式**：按需启动，满足大多数用户。
  - **Hub/Worker 模式**：适合需要常驻运行、会话分散在多台机器上的用户。

## 非目标

- 团队协作、多用户、权限系统和账号体系。
- 云端托管或 CodeSesh 运营的同步服务。
- 在 Worker 上远程执行命令或继续会话。
- 多 Hub、多主复制或通用任务调度。
- 修改、删除 Agent 原始历史。
- 自动合并不同机器上的同一会话。
- 对会话内容做 AI 总结、评分或推荐。

## 取舍原则

- **新增 Agent**：要求有真实样本，并覆盖用量、工具和删除行为。能力不足的 Agent 在支持说明中如实标注，不靠推测补齐。
- **单机与 Hub/Worker 共用数据语义**：同一数据目录只运行一种模式。切换模式时保留历史与用户状态。
- **来源消失不删除档案**：Agent 数据被删除后，已采集的会话仍保留，并标明来源状态。
- **性能结论必须实测**：方法见 [engineering/performance.md](./engineering/performance.md)。
- **前端首屏有预算**：重依赖按路由懒加载，由 bundle 测试守护。
