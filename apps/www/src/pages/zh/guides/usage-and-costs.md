CodeSesh 从受支持的 AI 编码会话记录中汇总 Token 和成本。先在总览选择日期范围，再按项目、Agent 或来源缩小范围。这些数字描述已建立索引的活动，不能代替服务商账单或订阅用量页面。

## 先确定时间和范围

启动 CodeSesh 后打开总览，选择最近一段时间或自定义日期。查看较早历史时，可以启动全部历史范围：

```sh
codesesh --days 0
```

只看一个项目时，在项目目录中运行：

```sh
codesesh --cwd . --days 0
```

也可以在界面中打开对应项目。Hub 模式下，通过来源筛选区分某台电脑与合并归档。对比数字时，保持日期和筛选条件一致。

默认启动范围是最近七个本地日历日。Worker 采集范围与 Hub 浏览窗口相互独立；改变 Hub 时间范围，不会要求 Worker 丢弃更早的源历史。

## 理解 Token 分类

输入和输出 Token 对应模型用量的不同部分。受支持的记录还可能提供推理、缓存读取和缓存创建 Token。字段是否存在、如何计数，取决于源 Agent 的记录方式和适配器对字段的解释。

不要在未确认定义时，把所有显示分类直接相加后与服务商数字比较。有些服务商会把缓存或推理用量包含在其他汇总字段中。模型分布和项目统计可以帮助定位用量来源，再打开会话检查上下文。

## 区分记录成本与估算成本

成本分解会区分来自 Agent 记录的金额与按模型单价计算的估算金额。记录成本来自源数据；估算成本依赖识别到的模型名称、Token 数量，以及 CodeSesh 使用的价格数据。

无法识别的模型、不完整的用量记录或缺失的价格，可能让成本统计不完整。显示零成本本身不能证明那次工作免费。模型标签或价格数据不同，也可能导致估算结果变化。

## 数字不符合预期时怎么查

1. 确认日期，以及项目、Agent、来源筛选符合你的对比目标。
2. 检查初次索引是否完成，Worker 是否还有待上传数据。
3. 打开相关会话，查看实际记录了哪些模型和 Token 分类。
4. 分别比较估算成本和记录成本。
5. 核对实际扣费时，以服务商账户记录为准。订阅费用、赠送额度、折扣，以及本地日志未记录的活动，不一定能与这份归档对应。

大量归档首次打开统计时可能需要等待。如果总览持续缓慢，反馈时附上 CodeSesh 版本与应用日志中的相关耗时。日志位置见[后台服务指南](/zh/guides/background-services/)。

## 从统计回到具体会话

高用量的项目或模型可以作为检查入口。通过[会话搜索与回放](/zh/guides/session-history/)查看对应对话和工具活动。需要汇总自己的多台电脑时，可以配置 [Hub 和 Worker](/zh/guides/multi-machine-sync/)。
