CodeSesh は対応する AI コーディング会話の記録からトークン数と費用を集計します。概要で期間を指定し、プロジェクト、Agent、ソースで絞り込みます。数値はインデックス済みの活動を示すもので、サービス提供元の請求書やサブスクリプションの使用量ページの代わりではありません。

## 期間と対象を先にそろえる

CodeSesh を起動して概要を開き、最近の期間か任意の日付を選びます。古い履歴を見るには全期間で起動できます。

```sh
codesesh --days 0
```

一つのプロジェクトを見る場合は、そのディレクトリで実行します。

```sh
codesesh --cwd . --days 0
```

画面からプロジェクトを開くこともできます。Hub ではソースの選択で一台分と全体を区別します。比較時は日付とフィルターをそろえてください。

既定の起動範囲は直近七日間のローカル暦日です。Worker の収集と Hub の表示範囲は別です。表示期間を変えても、Worker が古い履歴を破棄するわけではありません。

## トークンの区分を読む

入力と出力のトークンはモデル使用量の異なる部分です。対応する記録には推論、キャッシュ読み取り、キャッシュ作成のトークンも含まれる場合があります。利用できる項目と集計の意味は、元の Agent の記録とアダプターによる解釈に依存します。

定義を確認せず全区分を足し合わせてサービス提供元と比較しないでください。キャッシュや推論の使用量を他の合計に含めるサービスもあります。モデル分布とプロジェクトの集計で使用量の出所を調べ、会話を開いて内容を確認します。

## 記録された費用と推定額を区別する

費用の内訳では、Agent の記録にある金額と、モデル単価から計算した推定額を区別します。推定額にはモデル名の識別、トークン数、CodeSesh の価格データが必要です。

未知のモデル、不完全な使用記録、価格の欠落によって集計が不完全になる場合があります。表示額がゼロでも無料だったとは限りません。モデルのラベルや価格データの違いで推定額が変わることもあります。

## 予想と違う数値を調べる

1. 日付、プロジェクト、Agent、ソースの指定を確認します。
2. 初回のインデックス作成や Worker の送信が完了しているか確認します。
3. 関連する会話でモデル名とトークンの区分を調べます。
4. 推定額と記録された金額を分けて比較します。
5. 実際の請求はサービス提供元の記録で確認します。定額料金、クレジット、割引、ローカルログにない活動は、このアーカイブと一致しないことがあります。

大きな履歴では初回の統計表示に時間がかかる場合があります。遅い状態が続く場合は、CodeSesh のバージョンとアプリケーションログの所要時間を添えて報告してください。ログの場所は[バックグラウンド実行ガイド](/ja/guides/background-services/)で確認できます。

## 集計から会話へ進む

使用量の多いプロジェクトやモデルを手がかりに、[会話の検索と閲覧](/ja/guides/session-history/)で対話とツール操作を確認します。自分の複数端末をまとめる場合は [Hub と Worker](/ja/guides/multi-machine-sync/)を設定してください。
